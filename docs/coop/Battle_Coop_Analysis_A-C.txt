## C. Start of Battle (Trigger → First Turn)

1. **Link‑battle handshake** – The trainer see script (`trainer_see`) calls `battle_setup` which sets `gBattleTypeFlags` (see Section A) and spawns the link‑battle task.
2. **Task creation** – `CreateLinkBattleTask` (address **NÃO ENCONTRADO**) allocates a task that runs `Task_HandleSendLinkBuffersData` and `Task_HandleCopyReceivedLinkBuffersData`.
3. **Party exchange** – Both consoles pack their party data (6× Pokémon structs, 100 bytes each). Only the first three slots are sent; the partner’s party is sent as a compact summary (species, level, HP, status) – 32 bytes per Pokémon. The packet structure:
   - Header `0x10` (party sync), length `0xC0` (3 × 0x40), payload `[species][level][hp][status][... (rest of struct truncated)]`.
4. **Screen setup** – After receiving the partner’s party, each console executes `SetBattleScreen` which draws the VS screen. This routine is at **0x0803F1A4** (identified via pattern `bl 0x0804BC0C` followed by UI calls).
5. **First turn kickoff** – Once both sides have confirmed receipt (flags cleared), `gBattleMainFunc` is set to `BattleMain_ExecuteBufferTransfer` (address **0x08041A2C**, inferred from call chain). The first turn begins with each battler’s controller set as in Section A.
